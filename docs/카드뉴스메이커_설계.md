## 0. 한 줄 정의

**Figma 같은 자유 캔버스 없이, 텍스트·이미지만 넣으면 규칙 엔진이 조판해 카드뉴스를 뽑아주는 웹 인앱. AI(LLM/API) 사용 안 함 — 100% 결정론적, 클라이언트 사이드.**

## 1. 핵심 결정 (확정)

- **AI 미사용 확정.** 이유:
  1. API 토큰·비용·키 관리 없음, 오프라인 동작, 배포 공짜
  2. 카드뉴스는 "덱 안 일관성"이 중요 → AI의 매번 다른 결과는 오히려 독
  3. 포폴 서사: "AI에 기댄 게 아니라 **내가 설계한 룰 엔진**이 조판한다" = 디자인 시스템 사고 증명 (UX/UI 디자이너에게 API 호출보다 강한 카드)
- **캔버스(자유 배치) 제거 확정.** 사용자는 배치를 안 함. 시스템이 배치를 책임진다.
  - 사용자 = **콘텐츠 + 상위 선택(테마 등)** 만.
  - 무한 자유는 비전문가가 못생긴 결과를 만드는 원인 → **제약이 곧 기능.**

## 2. 다양성은 어디서 나오나 (가장 중요한 개념)

> **다양성 = AI가 아니라 "잘 설계된 조합 시스템"에서 나온다.**
> AI도 결국 학습 공간에서 샘플링할 뿐. 우리는 그 공간을 직접 큐레이션한다.

### ⚠️ 정확한 멘탈 모델 (오해 주의)
5~6개 템플릿이 **서로** 곱해지는 게 아니다. 템플릿은 **레이아웃 축 하나**이고,
그것이 **독립적인 다른 스타일 레이어들과 곱해져** 경우의 수가 폭발한다.

```
레이아웃 템플릿 6  ×  테마 8  ×  강조색 12  ×  그리드 3변형  ×  배경 4종
= 6,912 가지
```
- 템플릿만 6개면 → 그냥 6개 룩. (여기서 끝나면 걱정이 맞음)
- **독립 스위치(테마·색·그리드·배경)를 곱해야** 폭발한다.
- 덱 안에서 카드마다 내용 따라 템플릿 자동 전환 → **덱 단위 배열 경우의 수는 사실상 무한.**

### 곱셈의 레버리지 (재료 1개 추가 = 조합 수백~수천 개 생성)
이건 덧셈이 아니라 **곱셈**이다. 어느 축이든 값을 하나 더하면 나머지 축 전부와 곱해진다.

| 뭘 하나 추가하면 | 새로 생기는 조합 수 (예시 축 기준) |
|---|---|
| 템플릿 +1 | 8×12×3×4 = **1,152** |
| 테마 +1 | 6×12×3×4 = **864** |
| 강조색 +1 | 6×8×3×4 = **576** |
| 배경 +1 | 6×8×12×3 = **1,728** |

→ 템플릿 1개 추가 = +1이 아니라 **+1,152**. 작은 재료가 시스템 전체와 곱해져 복리처럼 불어남.
→ "왜 5~6개 템플릿만 만들어도 충분한가"의 답. **투자는 '재료 수'가 아니라 '축 설계'에.**
- ⚠️ 정직한 단서: 이 숫자는 **이론적 상한**. 사람 눈에 "확 다른" 조합은 일부이고, 각 재료의 완성도가 조합 품질을 좌우. 걱정할 지점은 조합 수가 아니라 **재료 하나하나의 완성도**.

### 핵심 UX 원칙
- **일관성은 카드 레벨(덱 안)** — 8장이 따로 놀면 안 됨.
- **다양성은 테마 레벨(프로젝트 간)** — 덱끼리는 달라야 함.
- AI-free 프리셋 시스템이 이 구조에 정확히 맞음 (타협이 아니라 올바른 도구).

## 3. 다양성 엔진 3종

**① 테마 프리셋 (디자이너가 저자)**
Editorial / Swiss / Brutalist / Pastel / Mono / Magazine … 성격이 완전히 다른 8~12벌.
각각 토큰 묶음(폰트·컬러·여백·배경). 스위칭 = 무드 전환.
→ 이미 있는 `tokens.css`가 이 엔진의 기반.

**② 파라메트릭 변주 ("Shuffle" 버튼)**
디자인이 안 깨지는 **안전 범위 안에서** 파라미터를 시드/랜덤으로 흔든다:
강조색 색상환, 그리드 변형, 타입 스케일 비율, 배경 생성(그라데이션·도형·패턴), 이미지 필터.
Shuffle 누를 때마다 새 시드 → 새 디자인. **무한 다양성의 체감**, 속은 100% 결정론적.

**③ 콘텐츠 반응형 템플릿 (규칙 엔진)**
카드 내용의 "모양"을 보고 규칙으로 레이아웃을 고른다. (아래 4장)

## 3.5 사용자 조작 레이어 — "레일 위의 직접조작" (구속된 직접조작)

조합 시스템 위에 **사용자 미세조작**을 얹으면 "가짓수 적다는 느낌"을 없애고 **저작감(agency)**을 준다.
단, **자유 조작이 아니라 레일 위 조작**이어야 한다. (자유 조작 = 캔버스 부활 = 우리가 없앤 그 문제)

**⚠️ 함정**: 아무 위치 이동/아무 크기/떠다니는 텍스트박스를 열면 → 카드 깨짐 + 덱 일관성 붕괴 +
"시스템이 품질 보장" 포폴 서사 격하. 반드시 스냅/클램프/슬롯 삽입으로 구속.

| 단계 | 기능 | 위험/비용 | 방침 |
|---|---|---|---|
| **1군 (강추)** | 카드 순서변경, 카드별 템플릿 스왑, 테마/색/배경 스왑, Shuffle, 이미지 초점 이동, 강조 토글 | ~0 | 안전·저비용·저작감 큼 → 우선 구현 |
| **2군 (조건부)** | 슬롯 스냅 이동, 단계형(S/M/L) 크기조절, 슬롯에 텍스트 추가 | 중 | 스냅/클램프 필수. 여력 될 때 |
| **3군 (피하기)** | 자유 x/y 드래그, 자유 px 리사이즈, 요소별 임의 폰트/색 | 고 | **시스템 철학·품질 보장 붕괴 → 하지 않음** |

**개념 구분 (중요)**:
- **조합 시스템** = 덱끼리 달라 보이게 (between-deck 다양성)
- **조작 레이어** = 사용자에게 "내가 만들었다" 저작감 (agency) — "가짓수 적은 느낌"의 진짜 해법은 이쪽
- 조작 축(크기 단계·초점 위치·강조 토글 등)도 전부 **곱셈 축** → 조합 수 추가 증가.

**한 줄 원칙: "레일 위의 조작"이면 예스, "자유 캔버스"면 노.**

## 4. 작동 엔진 (파서 + 규칙, AI 아님)

"프롬프트 넣으면 디자인됨"의 정체 = **콘텐츠 모양 → 규칙 → 레이아웃 선택.**

| 사용자가 넣은 콘텐츠 | 자동으로 뜨는 템플릿 |
|---|---|
| 이미지 1 + 짧은 제목 | 풀블리드 표지 |
| 제목 + 항목 3~5개 | 번호 리스트 카드 |
| 따옴표로 감싼 문장 | 인용 카드 (큰 세리프 = Newsreader) |
| 숫자+단위가 주내용 ("89%") | 통계 강조 (초대형 숫자) |
| `?`로 끝나는 한 줄 | 질문 카드 |
| 이미지 없는 긴 문단 | 본문 텍스트 (자동 축소) |

### 파이프라인
```
입력(텍스트+이미지) → 파서(카드 분할) → 규칙 매칭(템플릿 선택)
  → 전역 테마 토큰 적용 → 렌더(고정 캔버스) → 내보내기(PNG/캐러셀 zip + 캡션)
```
- 고정 캔버스: 1:1 또는 4:5 한 종류
- 자동 조판 가드레일: 슬롯별 글자수 제한+자동 축소/줄바꿈, 이미지 스마트 크롭+가독성 오버레이

## 5. 입력 방식 — [확정] B 비주얼 슬롯-채우기 ✅

편집기 재사용(4.6) 결정에 따라 **B로 확정**: 템플릿 고르기 → 슬롯 채우기(비주얼).
- A(마크다운 문법)는 후순위/보류. 여력 되면 "붙여넣기 → 카드 자동분할" 진입점으로 나중에 얹을 수 있음.

(참고) 이전 두 후보:
- A. 글 문법(마크다운식): `---` 카드 분할 + 태그. 프롬프트 감성 큼, 문법 학습 필요.
- B. 칸 채우기: 배울 것 없음. ← 채택.

> 예시(A안 문법):
> ```
> ---
> 표지
> # 프론트엔드 없이, 3시간 만에
> !cover.jpg
> ---
> 통계
> 89%
> "다시 쓰고 싶다"고 답한 사용자
> ---
> 인용
> "제약이 창의를 만든다"
> ```

## 8. ★ 방향 전환 (2026-07-27): 생성-우선 플로우 — "PPT와 다른 이유"

**문제 인식(사용자):** 빈 캔버스에서 한 장씩 만들면 = "기능 적은 PPT". 존재 이유가 없음.
**존재 이유(확정):** **PPT보다 세밀함은 떨어져도 속도로 압도한다.** 그 무기 = "생성 → 선택 → 다듬기".
이것이 SSOT의 "AI 없이 룰 엔진으로 다양성 생성"을 **실제 앱 플로우로 구현**한 것.

### 새 앱 플로우 (4단계)
```
① 설정(브리프) 화면 — 주제 / 카드 수 / 구성 레시피 / (선택)무드
② 룰 엔진이 3~5개 "뼈대 덱" 자동 생성 (결정론적 조합 샘플링)
③ 사용자가 하나 선택 (선택 안 된 시안은 임시저장 → 갈아탈 수 있음)
④ 편집기(현재 화면)에서 상세 다듬기 — 텍스트 위치·이미지·세부수정
```
- **현재 편집기 = ④단계.** 버려지는 것 아님.

### ⚠️ 정직한 경계 (AI 없음)
엔진이 자동 생성하는 것 = **구조(템플릿 순서·장수) + 스타일(테마·색·레이아웃 변형) + 옵션(3~5 시안).**
**글(카피)은 사용자가 타이핑.** 단, 배치·조판·스타일·선택이 이미 끝난 "완성 직전 뼈대"에 글만 넣으므로 **PPT보다 압도적으로 빠름** — 이게 속도 무기의 정체.

### ①설정 화면이 물어볼 것 (초안)
- 주제/제목 (표지에 들어감)
- 카드 수 (예: 5)
- 구성 레시피 프리셋 (예: 정보전달형=표지+리스트+통계+CTA / 스토리형=표지+본문×3+인용)
- (선택) 무드/테마 취향 — 미선택 시 엔진이 여러 테마로 시안 생성

### 빌드 순서 (리서치 이후)
리서치 → 프롬프트화(엔진 주입) → **① 생성 플로우** → ② 템플릿 변형 심화 → ③ 인스펙터(세부수정) → ④ 이미지

## 9. 리서치 계획 (다음 단계 — 엔진의 재료)

> AI가 없으니 **리서치의 깊이 = 결과물의 질.** 조사해서 전부 데이터/규칙으로 "프롬프트화".

**리서치 대상:**
1. **테마 카테고리** — 카드뉴스가 실제로 나뉘는 무드/스타일이 몇 가지이고 무엇인지
   (예상: 정보전달/뉴스형 · 감성/에세이형 · 비즈니스/리포트형 · 트렌디/Z세대형 · 미니멀/에디토리얼 · 브랜드/프로모션 …)
2. **테마별 카드뉴스 디자인 레퍼런스** — 각 스타일의 실제 관행: 레이아웃 구성, 타이포, 색 사용, 자주 쓰는 카드 종류(표지·목차·본문·강조·인용·통계·CTA), 구성 순서
3. **프롬프트화** — 위를 구체 데이터로: 테마 토큰(일부 완료) + 스타일별 템플릿 변형 + placeholder 카피 패턴 + 추천 구성 레시피(장수·순서)

**산출물:** 테마 카테고리 N종 + 각 테마의 디자인 스펙 → 생성기의 building blocks + 레시피.
