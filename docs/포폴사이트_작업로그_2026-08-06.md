## 1. 신설 — 어바웃 페이지 (`about.html`)

레퍼런스: [adcker.com/services](https://adcker.com/services/)
그 페이지의 뼈대는 **"숫자 목록으로 먼저 훑고, 아래에서 하나씩 펼친다"** 는 2단 구성이다.

```

   ↓

           ( 03 ) Experience ( 04 ) Off the clock
   ↓
같은 항목을 아래에서 하나씩 펼쳐 설명

### 새로 만든 부품은 3개뿐
| 부품 | 용도 |
|---|---|
| `.ax` / `.ax-list` | 숫자 인덱스 목록 (호버 시 안으로 밀림) |
| `.tl` / `.tl-row` | 연대기 표 (연도 200px / 내용 1fr) |
| `.hobby` | 취미 3열 |

나머지(`.case-sec`, `.case-h`, `.case-body`, `.case-next`, 헤더·푸터·챗봇)는
**케이스 스터디 부품을 그대로 재사용**했다. 그래서 톤이 흔들리지 않는다.

### 연대기 — 연도만 표기한다
```
2014 — 2023  한밭대학교 시각디자인
2016 — 2018  육군 병장 만기전역 · 포병
2019         ㈜테크앤 · 디자인
2023 — 2024  파스쿠찌 바리스타
2024 — 2025  에스텍시스템 · 신라호텔 보안
2026         이젠아카데미 강남캠퍼스
2026         GOI → ILKW → W:RUN
```

⚠️ **월 단위를 쓰지 않는다.** 월까지 적으면 읽는 사람이 기간을 계산하기 시작하고,
2025.10 → 2026.02 의 4개월이 눈에 보인다. 연도만 쓰면 `2025, 2026` 으로 붙는다.
연대기의 목적은 "어떻게 여기까지 왔나"지 근태 확인이 아니다.

### 바리스타·보안을 숨기지 않고 프레임을 바꿨다
각 줄에 "그 일에서 무엇을 봤는지"를 한 줄씩 달았다.
- 파스쿠찌 → 사람이 무엇을 망설이고 무엇을 그냥 지나치는지 봤다
- 신라호텔 보안 → 말을 줄이고 동선으로 설명하는 법을 배웠다

03 EXPERIENCE 의 리드도 `Every job was about watching people.` 로 맞췄다.
**"돌아온 사람"이 아니라 "계속 사람을 봐 온 사람"** 이 된다.

### 🔴 발견 — 군복무 기간이 인턴과 겹쳐 있었다
연대기로 늘어놓자마자 드러났다. 이력서에선 항목이 따로라 안 보이던 것이다.

| | 잘못된 기록 | 실제 |
|---|---|---|
| 육군 | 2016.12 ~ **2019.09** (33개월) | 2016.12 ~ **2018.09** (21개월) |

병장 만기전역이 33개월일 수 없다. 2016.12 입대 + 21개월 = 2018.09 로 `09` 월은 그대로였고
**연도만 오타**였다. 고치자 인턴(2019.01~) 과도 자연스럽게 이어졌다.

**고친 곳 3군데:** `about.html` (연대기 · Education) · `api/knowledge.js`
⚠️ **입사지원서 원본(`김종욱 입사지원서.docx`)도 확인 필요** — 여기 값이 거기서 넘어왔다.

### 취미 — 사진은 "있으면 켜지는" 구조로
사진 3장을 한 번에 준비하기 어려워, 마크업을 미리 넣고
**파일이 없으면 `js/main.js` 가 `<figure>` 를 지운다.**
→ 3장이 다 없어도 빈 회색 박스가 보이지 않고, 파일을 넣는 즉시 아무 수정 없이 켜진다.

```
원본이 전부 가로/정사각이라 3:4 세로로 중앙 크롭했다.
게임 사진만 **크롭을 밀어서** 잡았다 (인형뽑기 원본은 사람 뒤통수가 화면 절반이었고,

## 2. 신설 — 모바일 안내 화면 (`.mgate`)

이 사이트는 1920 캔버스를 통째로 `scale()` 하는 구조라, 화면이 좁아지면
**레이아웃이 깨지는 게 아니라 글자가 같이 작아진다.**

| 화면 폭 | `--sf` | 본문 18px 이 실제로 |
|---|---|---|
| 1920 | 0.92 | 16.5px ✅ |
| 1280 | 0.61 | 11px ⚠️ |
| 375 | 0.17 | **3.1px** ❌ |

→ 900px 이하에서는 본문 대신 안내 화면을 보여준다.

**핵심은 "PC에서 보세요"로 끝내지 않는 것.** 세 프로젝트가 원래 모바일 앱/반응형 웹이라,
폰으로 들어온 사람에게 **지금 그 폰에서 바로 써볼 수 있는 링크 3개**를 준다.
사과가 아니라 안내가 된다.

```css
@media (max-width: 900px) {
  body > *:not(.mgate) { display: none !important; }
  .mgate { display: block; }
}
```

실측 검증 (375×812): 안내 화면 외 노출 요소 **0개** · 가로 스크롤 없음 ·
문서 높이 정확히 812px(스크롤 불필요) · 링크 터치 영역 89px(권장 44px의 2배).
1440px 에서 기존 동작 **손상 0**, 창을 좁혔다 넓히면 `fit()` 이 다시 돌아 복구된다.

⚠️ 진짜 반응형을 만들면 **이 CSS 블록 + 각 페이지 `.mgate` 마크업만 지우면** 된다.

## 3. 멘토 피드백 반영

### 3-1. 🔴 어바웃 목차를 누르면 제목이 헤더에 가림

**CSS `scroll-margin-top` 으로는 못 고친다.** 목적지가 `scale(--sf)` 된 무대 안에 있어서
여백도 배율만큼 같이 줄어드는데, 헤더는 배율과 무관한 실제 px 라 양이 안 맞는다.

→ 헤더 높이를 실측해 직접 계산한다. 페이지 안 `#앵커` 링크 전부에 공통 적용.
```js
function anchorOffset() { return header.getBoundingClientRect().height + 24; }
```
검증: ( 01 )~( 04 ) 네 개 모두 제목이 **y=100** 에 선다 (헤더 51px 아래 49px 여유).

### 3-2. 프로젝트 이미지 — 커튼 리빌 (뮤자인 방식)

멘토: *"프로젝트 1,2,3 이미지 인터랙션이 지금은 없는 것 같다"*
→ 기존 부유(90px 상승 + 페이드)가 **너무 약해서 눈에 안 띄었다.**

`clones/05`(뮤자인)의 `.img.motion` 을 가져왔다. 원본은 흰 오버레이 height 를 90%→0% 로
줄이는데, 여기서는 **`clip-path` 로 같은 결과**를 낸다 — `<img>` 에는 `::after` 를 못 붙인다.

```css
.curtain { clip-path: inset(92% 0 0 0); }
.curtain.is-open { clip-path: inset(0 0 0 0); transition: clip-path 1.15s cubic-bezier(.16,1,.3,1); }
```

이미지 9장은 **부유 대상에서 빼고** 커튼으로 대체했다 (겹치면 등장이 두 번 일어난다).
기여도 카드·태그 3개는 기존 부유 유지.

#### ⚠️⚠️ 이날 가장 큰 실수 — IntersectionObserver 의 자기모순
처음에 `threshold: 0.15` 로 만들었다가 **이미지가 8% 만 보인 채 영영 안 열렸다.**

```
요소가 clip-path 로 자기를 8% 로 잘라 둠
  → 교차 '비율'이 8% 를 못 넘음
  → threshold 15% 를 영영 못 넘음
  → 안 열림 → 계속 8%
```

**닫혀 있어서 못 열리는 구조였다.**
→ IO 를 걷어내고, 이미 매 프레임 도는 `onScroll` 에 붙였다.
비율이 아니라 **좌표만 보므로** 자기모순이 생길 수 없다.

**교훈: 자기 자신을 가리는 요소에 IntersectionObserver 의 `threshold` 를 쓰지 말 것.**

#### 실패해도 안전하게
`.curtain` 클래스는 **JS 가 붙인다.** CSS 에만 두면 JS 가 죽었을 때 이미지가 영영 8% 로 남는다.
지금은 JS 가 안 돌면 클래스가 안 붙어 이미지가 그냥 정상적으로 보인다.

### 3-3. 클론코딩 미리보기 — 스크롤바 숨김

`iframe` 안쪽은 다른 문서라 **바깥 CSS 로 스크롤바를 못 없앤다.**
→ 프레임을 스크롤바 폭만큼 크게 잡아 컨테이너 밖으로 밀어내고 `overflow:hidden` 으로 자른다.

```
        1280 → 1300          800 → 820
scale 0.28125 후  366px          231px
컨테이너          360px          225px       ← 6px 씩 잘려나감 (여기에 스크롤바)
```
실측: 안쪽 스크롤바 15px · 가로/세로 모두 컨테이너 밖 ✅
덤으로 콘텐츠 폭이 1265 → **1285** 가 되어 의도한 1280 에 더 가까워졌다.
여유를 20px 로 잡은 이유는 **스크롤바 폭이 OS·브라우저마다 다르기 때문**(15~17px).
